## What the data changed (design consequences)

| Finding (source) | Consequence |
|---|---|
| PACE: waiting ≤ 24 h cuts *average* CI by 33%, but marginal CI is flat at 498–658 g/kWh (grid §8) | Report both. Average (EIA's hourly CO₂, primary per E09) and consumption-based figures sit side by side, with a marginal proxy in **skeptic mode**. We never call it "avoided". |
| Moving PACE → BPAT/CISO/NEVP cuts 94/66/42% (grid §8) | Move vs wait is in the core, with capacity limits and migration rules so the answer isn't trivially "go to BPAT". |
| In PACE, carbon and demand peaks don't coincide (r = −0.18). In NYIS/ISNE/PJM/DUK the peak hours are 20–36% dirtier | **Second insight: "clean hours ≠ rush hours"** — the emissions-first router moves Utah work from coal nights to solar middays, not out of the 17–20 h peak. |
| Honest day-ahead weather exists only as Previous Runs `_previous_day2`, all variables from 2024-03-01 (grid §9) | Primary model is weather-free (long history). A weather-augmented model is compared on validation; option (b) or (c) is chosen in the spec. Weather always comes from `weather.safe_previous_day`. |
| The BA's DF is published at 11:00 ET on day D; PJM is +1 h, CISO +1 h since 2022; imputed hours often equal DF | DF is a baseline only, aligned per BA on validation. Imputed hours are excluded from scoring; spike rule applies. |
| EIA publishes hourly CO₂ per BA (production and consumption) in per-BA workbooks | That is the primary CI signal. Our fuel-mix CI is the fallback and the input to the marginal proxy. |
| Acme Seren: pre-training is 0.9% of jobs but 69.5% of GPU-hours; queues are about 1 s today; load is flat at 61% of 2,288 GPUs | Levers: start time and pause/resume of long jobs. Allowed wait is an `assumed` sweep. A GPU capacity cap is mandatory. 0.7 kWh/GPU-h at the meter (swept 0.4–2.0). Week-block bootstrap aligned by local wall clock. Scale multiplier stated. |
| Price peaks follow net load (r 0.53–0.78), not demand; PACE day-ahead exists only since EDAM (2026-05-01); CAISO keyless from 2023-07 | Stress index on net load is validated. Prices are a Should, labeled "wholesale scenario"; PACE real-time vs EDAM is pre-registered. |
| WACM/WAUW retire 2026-04-01 (SWPW, BHBA new) | Keep them out of the core region set. |

**Core region set:** PACE (hero), BPAT, CISO, NEVP, AZPS, PSCO, ERCO, SWPP, MISO, PJM. Optional: IPCO, NYIS.

## How each stage is built (subagent-driven development)

1. Write the stage plan with superpowers:writing-plans in `docs/superpowers/plans/`. Sol (`-p review`) verifies it.
2. Run one fresh subagent per task, at most 3 at once, each in its own worktree with shared data via `worktree.symlinkDirectories`.
   - Use test-driven development for metrics, the simulator, leakage, and accounting.
   - Each task is reviewed for spec compliance and code quality by the `code-reviewer` agent. Codex reviews tasks that touch leakage or metrics.
3. PR → the lead merges (fast-forward or squash) → update the stage notebook and `docs/decisions.md` → gate.

## Seeing the UI from the MacBook

- **Private links.** The mockups and the evidence journal are claude.ai Artifacts. Screenshots and clips are sent to your device at each UI checkpoint.
- **SSH tunnel to the live dev app.** On the Mac:
  ```
  ssh -N -L 5173:localhost:5173 nvidia@<DGX address>
  ```
  Then open `http://localhost:5173`. The DGX address is printed at setup. Nothing is exposed publicly.
- **Pull and run.** On the Mac (Node ≥ 20 and GitHub access to the private repo):
  ```
  git pull
  cd web && npm ci && npm run dev
  ```
  Or `npm run build && npm run preview`, which is also the offline demo rehearsal (first dry-run Tue ~18:00).
